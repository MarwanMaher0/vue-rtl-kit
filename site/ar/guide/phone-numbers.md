# أرقام الهاتف

تواجه نماذج الدفع والتسجيل العربية مشكلتين في أرقام الهاتف في آنٍ واحد. أولًا، يكتب الزوّار الأرقام بالأرقام العربية الهندية (`٠١٢٣`) أو الفارسية (`۰۱۲۳`)، مع مسافات وشرطات ونقاط وأقواس ومحارف تحكم ثنائية الاتجاه وبادئات دولية مثل `00` أو `+` وصفر الاتصال المحلي — فيرفض التعبير النمطي البسيط عملاء حقيقيين. ثانيًا، حين يُعرض رقم دولي منسّق مثل `+966 50 123 4567` داخل جملة عربية، تنقل خوارزمية Unicode ثنائية الاتجاه علامة `+` إلى اليمين بصريًا وتعكس ترتيب مجموعات الأرقام.

الدوال `normalizePhone` و`validatePhone` و`formatPhone` دوال نقية (بلا أي استيراد من Vue وبلا أي اعتماديات خارجية وبلا وصول إلى DOM) تغطي خطط الترقيم الوطنية لثماني دول عربية: السعودية (`SA`) والإمارات (`AE`) والكويت (`KW`) وقطر (`QA`) والبحرين (`BH`) وعُمان (`OM`) ومصر (`EG`) والأردن (`JO`).

```ts
import { formatPhone, normalizePhone, validatePhone } from 'vue-rtl-kit'

const e164 = normalizePhone('٠٥٠ ١٢٣ ٤٥٦٧', { defaultRegion: 'SA' })
// '+966501234567'

validatePhone('0020 (0)10-1234-5678', { mobileOnly: true })
// { valid: true, e164: '+201012345678', region: 'EG', type: 'mobile' }

formatPhone(e164, { locale: 'ar-EG', numberingSystem: 'arab' })
// '\u2066+٩٦٦ ٥٠ ١٢٣ ٤٥٦٧\u2069'
```

## المناطق المدعومة وخطط الترقيم التنظيمية

تتضمن القواعد المدمجة رمز كل دولة وسلوك صفر الاتصال المحلي وأطوال الرقم الوطني الصالحة وبادئات الجوال والهاتف الثابت وتجميع الأرقام الدولي القياسي وفق خطة الترقيم الوطنية المعتمدة لدى كل هيئة تنظيمية:

| المنطقة | الرمز | صفر محلي `0` | قواعد الجوال | قواعد الثابت | التجميع | خطة الهيئة التنظيمية |
| --- | --- | --- | --- | --- | --- | --- |
| `SA` (السعودية) | `+966` | نعم | 9 أرقام: `50` و`51` و`53`–`59` | 9 أرقام: `11`–`14` و`16` و`17` | `2-3-4` (`+966 50 123 4567`) | خطة الترقيم الوطنية لهيئة الاتصالات والفضاء والتقنية CST (سابقًا CITC) |
| `AE` (الإمارات) | `+971` | نعم | 9 أرقام: `50` و`52` و`54` و`55` و`56` و`58` | 8 أرقام: `2` و`3` و`4` و`6` و`7` و`9` | الجوال `2-3-4`؛ الثابت `1-3-4` | خطة الترقيم الوطنية لهيئة تنظيم الاتصالات والحكومة الرقمية TDRA |
| `KW` (الكويت) | `+965` | لا | 8 أرقام: `5` و`6` و`9` و`41` | 8 أرقام: `2` | `4-4` (`+965 5012 3456`) | خطة الترقيم الوطنية للهيئة العامة للاتصالات وتقنية المعلومات CITRA |
| `QA` (قطر) | `+974` | لا | 8 أرقام: `3` و`5` و`6` و`7` | 8 أرقام: `4` | `4-4` (`+974 5512 3456`) | خطة الترقيم الوطنية لهيئة تنظيم الاتصالات CRA |
| `BH` (البحرين) | `+973` | لا | 8 أرقام: `3` و`66` | 8 أرقام: `1` | `4-4` (`+973 3612 3456`) | خطة الترقيم الوطنية لهيئة تنظيم الاتصالات TRA البحرين |
| `OM` (عُمان) | `+968` | لا | 8 أرقام: `7` و`9` | 8 أرقام: `2` | `4-4` (`+968 9212 3456`) | خطة الترقيم الوطنية لهيئة تنظيم الاتصالات TRA عُمان |
| `EG` (مصر) | `+20` | نعم | 10 أرقام: `10` و`11` و`12` و`15` | 9 أرقام: `2` ورموز المحافظات؛ 8 أرقام: `3` و`15` | الجوال `2-4-4`؛ القاهرة `1-4-4`؛ الإسكندرية `1-3-4`؛ المحافظات `2-3-4`؛ ثابت العاشر `15` `2-3-3` | خطة الترقيم الوطنية للجهاز القومي لتنظيم الاتصالات NTRA |
| `JO` (الأردن) | `+962` | نعم | 9 أرقام: `77` و`78` و`79` | 8 أرقام: `2` و`3` و`5` و`6` | الجوال `2-3-4`؛ الثابت `1-3-4` | خطة الترقيم الوطنية لهيئة تنظيم قطاع الاتصالات TRC |

تعمل الكويت وقطر والبحرين وعُمان بخطط ترقيم مغلقة من 8 أرقام دون صفر اتصال محلي. أما السعودية والإمارات ومصر والأردن فتستخدم صفر الاتصال المحلي `0`، لذا يُقبل صفر واحد في بداية الرقم المحلي (`050 123 4567`) وكذلك مباشرةً بعد رمز الدولة (`+966 (0)50 123 4567`).

## تطبيع المدخلات

تنظّف `normalizePhone(value, options?)` مدخلات المستخدم وتعيد صيغة E.164 القياسية (`+966501234567`) أو سلسلة فارغة `''` إذا لم يكن المدخل رقمًا صالحًا ضمن المناطق المدعومة.

```ts
import { normalizePhone } from 'vue-rtl-kit'

normalizePhone('٠٥٠ ١٢٣ ٤٥٦٧', { defaultRegion: 'SA' })        // '+966501234567'
normalizePhone('+۹۷۱ (۰)۵۰-۱۲۳.۴۵۶۷')                          // '+971501234567'
normalizePhone('0020 010 1234 5678')                           // '+201012345678'
normalizePhone('\u2066+965 5012 3456\u2069')                   // '+96550123456'
normalizePhone('+971 50 123 4567', { defaultRegion: 'EG' })    // '+971501234567' — رمز الدولة الصريح يغلب
normalizePhone('050 123 4567')                                 // '' — بلا رمز دولة ولا defaultRegion
normalizePhone('+966 50 abc 4567')                             // '' — تُرفض الحروف
```

تمر عملية التطبيع بالخطوات الآتية:

- إزالة جميع محارف التحكم ثنائية الاتجاه في Unicode (`LRM` و`RLM` و`ALM` والتضمينات والتجاوزات ومحارف العزل).
- تحويل الأرقام العربية الهندية (`٠`–`٩`) والفارسية (`۰`–`۹`) إلى أرقام غربية `0`–`9` عبر `transliterateDigits`.
- إزالة المسافات (بما فيها المسافة غير القابلة للكسر) والأقواس `()` والنقاط `.` والشرطات (`-` و`–` و`—` و`−`).
- قبول البادئتين الدوليتين `+` و`00`، ورمز الدولة المباشر متبوعًا بطول وطني صالح، وصفر محلي واحد لدول `SA` و`AE` و`EG` و`JO`.
- رفض أي حروف (لاتينية أو عربية) أو رموز غير رقمية بدل حذفها بصمت.

## التحقق من الرقم

تعيد `validatePhone(value, options?)` نتيجة منظّمة تحتوي على صيغة E.164 والمنطقة المطابقة ونوع الخط (`'mobile'` أو `'fixed'`) وسبب الرفض `reason` عند عدم الصلاحية.

```ts
import { validatePhone } from 'vue-rtl-kit'

validatePhone('010 1234 5678', { regions: ['EG'], mobileOnly: true })
// { valid: true, e164: '+201012345678', region: 'EG', type: 'mobile' }

validatePhone('+966 11 234 5678', { mobileOnly: true })
// { valid: false, e164: '', region: 'SA', type: 'fixed', reason: 'prefix' }

validatePhone('+966 50 123 4567', { regions: ['AE', 'EG'] })
// { valid: false, e164: '', region: 'SA', reason: 'region' }

validatePhone('+966 50 123')
// { valid: false, e164: '', region: 'SA', reason: 'length' }

validatePhone('هاتف +966 50 123 4567')
// { valid: false, e164: '', reason: 'letters' }
```

| السبب `reason` | متى يُعاد |
| --- | --- |
| `'empty'` | المدخل فارغ أو ليس سلسلة نصية أو لا يحتوي إلا على مسافات وفواصل ومحارف اتجاه. |
| `'letters'` | المدخل يحتوي على حروف (لاتينية أو عربية وغيرها) أو رموز غير مسموح بها مثل `#` أو `*` أو `/`. |
| `'region'` | رمز الدولة خارج المناطق الثماني، أو الرقم محلي بلا `defaultRegion` (ولم يحدّد `regions` منطقة واحدة)، أو المنطقة المطابقة خارج قائمة `options.regions`. |
| `'length'` | عدد أرقام الرقم الوطني لا يطابق خطة الترقيم في المنطقة للبادئة المعطاة. |
| `'prefix'` | البادئة الوطنية غير مخصّصة في خطة المنطقة، أو علامة `+` في موضع غير صحيح، أو رُفض رقم خط ثابت بسبب `mobileOnly: true`. |

حين تحتوي `options.regions` على منطقة واحدة فقط (مثل `{ regions: ['SA'] }`) ويغيب `defaultRegion`، تُعتمد تلك المنطقة افتراضيًا للأرقام المحلية. أما عند تمرير أكثر من منطقة (مثل `{ regions: ['SA', 'AE'] }`) فمرّر `defaultRegion` أيضًا إذا أردت تحليل الأرقام المحلية التي تفتقر إلى رمز الدولة.

## التنسيق وعزل الاتجاه

تجمّع `formatPhone(e164, options?)` الأرقام وفق اصطلاح كل منطقة، وتختار شكل الأرقام حسب `locale` و`numberingSystem`، وتغلف الناتج بـ `U+2066 LRI` ... `U+2069 PDI` افتراضيًا فتبقى علامة `+` على اليسار بصريًا داخل النص العربي.

```ts
import { formatPhone } from 'vue-rtl-kit'

formatPhone('+966501234567')
// '\u2066+966 50 123 4567\u2069'

formatPhone('+201012345678', { locale: 'ar-EG' })
// '\u2066+٢٠ ١٠ ١٢٣٤ ٥٦٧٨\u2069'

formatPhone('+201012345678', { locale: 'ar-EG', numberingSystem: 'latn' })
// '\u2066+20 10 1234 5678\u2069'

formatPhone('+966501234567', { locale: 'ar', numberingSystem: 'arab', isolate: false })
// '+٩٦٦ ٥٠ ١٢٣ ٤٥٦٧'
```

- القيمة الافتراضية لـ `locale` هي `'en'`. وعند غياب `numberingSystem` يتبع شكل الأرقام ما تقرره `Intl.NumberFormat(locale)` (`'latn'` في `en` و`ar` في محركات ICU الحديثة، و`'arab'` في `ar-EG` و`ar-SA`، و`'arabext'` في `fa`). مرّر `numberingSystem` صراحةً كلما أردت تطابق الأرقام بين الخادم والمتصفح.
- القيمة الافتراضية لـ `isolate` هي `true`، فتغلف النتيجة بـ `LRI` (`\u2066`) ... `PDI` (`\u2069`). مرّر `isolate: false` للحصول على نص عادي بلا عزل (مثل قيمة حقل `<input>` أو نص رسالة قصيرة).
- مع `LRI ... PDI` تحافظ الأرقام الغربية (`latn`) على بقاء علامة `+` في اليسار بصريًا وعلى ترتيب مجموعات الأرقام من اليسار إلى اليمين داخل الجمل العربية. ومع الأرقام العربية الهندية (`arab`) يُبقي `LRI ... PDI` علامة `+` في اليسار بصريًا، بينما تحلّ خوارزمية Unicode UAX #9 المسافات بين مقاطع الأرقام العربية الهندية (`AN`) من اليمين إلى اليسار؛ لذلك تعرض أغلب واجهات الدفع العربية أرقام الهاتف الدولية باستخدام `numberingSystem: 'latn'`.
- المدخل الفارغ أو غير المعروف يعيد `''` دون إضافة محارف عزل.

## نموذج دفع مع v-digits

ادمج التوجيه [`v-digits`](/ar/guide/v-digits) على حقل الإدخال مع `normalizePhone` و`validatePhone` و`formatPhone` حتى يكتب العميل بالأرقام العربية الهندية أو الفارسية بطبيعية بينما يرسل النموذج صيغة E.164 نظيفة ويعرض تأكيدًا سليم الاتجاه:

```vue
<script setup lang="ts">
import { computed, ref } from 'vue'
import { formatPhone, normalizePhone, validatePhone } from 'vue-rtl-kit'

const raw = ref('')
const result = computed(() => validatePhone(raw.value, { regions: ['SA'], mobileOnly: true }))
const e164 = computed(() => normalizePhone(raw.value, { defaultRegion: 'SA' }))
const preview = computed(() => formatPhone(e164.value, { locale: 'ar', numberingSystem: 'latn' }))
</script>

<template>
  <form dir="rtl" lang="ar">
    <label>
      رقم الجوال
      <input v-model="raw" v-digits type="text" inputmode="tel" placeholder="050 123 4567">
    </label>
    <p v-if="result.valid">سيصل رمز التحقق إلى {{ preview }} خلال لحظات.</p>
    <p v-else-if="raw">الرقم غير صالح ({{ result.reason }})</p>
  </form>
</template>
```

تعمل الدوال الثلاث بصورة نقية ولا تلمس `window` أو `document`، فتنتج المخرجات نفسها تمامًا أثناء العرض على الخادم SSR. راجع [مرجع API](/ar/api#phone) للاطلاع على التواقيع والأنواع الكاملة.
